# Early Prediction of Knee Osteoarthritis Progression Using Machine Learning

> **A Machine Learning Research Prototype & Clinical Decision-Support Project**  
> *Developed for AIML Engineering Mini Project*

---

## ⚠️ Important Medical & Research Disclaimer

> **This project is a research and educational machine learning prototype and is NOT a medical diagnostic tool.**  
> The predictions generated by the system represent probabilistic risk estimates derived from statistical models and **must not be used for clinical decision-making, diagnosis, or treatment planning**.  
> The system does **not** claim to diagnose osteoarthritis or definitively determine whether a patient will develop severe disease. It is designed solely to investigate whether baseline clinical data contain predictive signals for disease progression.

---

## 📌 Problem Statement & Objectives

### Core Real-World Problem
Knee Osteoarthritis (OA) is a degenerative joint disease affecting millions worldwide. While existing diagnostic tools detect current OA severity, identifying which patients will experience **rapid, meaningful progression** over future years remains a critical clinical challenge.

### Key Project Objective
Build a machine learning research pipeline that uses structured patient/clinical information available at an **early baseline stage ($T=0$)** to predict the risk of meaningful knee osteoarthritis progression during a future follow-up period.

### Why Predicting Progression Matters
- **Early Identification**: Helps clinicians identify patients who may warrant closer monitoring or earlier preventive interventions.
- **Different from Detection**: Detecting existing OA relies on current damage; predicting progression anticipates future joint deterioration using baseline risk factors.

## 📊 Dataset & Target Definition

### Dataset Source
This project is designed for the **Osteoarthritis Initiative (OAI)** dataset, a multi-center longitudinal prospective observational study of knee OA funded by the NIH.
- **Official Access**: [NIH NIMH Data Archive (NDA) OAI Portal](https://nda.nih.gov/oai/)
- **Data Files**: Baseline clinical features (`AllClinical00.txt`) and radiographic scores (`kxr_sq_bu00.txt`, `kxr_sq_bu06.txt`).

### Progression Target Definition
The target outcome $Y \in \{0, 1\}$ is defined as binary radiographic OA progression over the follow-up window (e.g. 48 months):

$$Y = \begin{cases} 1 & \text{if } (KL_{\text{followup}} - KL_{\text{baseline}} \ge 1) \\ 0 & \text{otherwise} \end{cases}$$

Where **KL** refers to the Kellgren-Lawrence radiographic severity grade (0 to 4). Patients with end-stage baseline OA ($KL=4$) are excluded as progression cannot be radiographically measured beyond grade 4.

---

## 🛡️ Preventing Data Leakage

Medical machine learning models can easily overestimate performance if leakage occurs. This project implements strict leakage prevention protocols:

1. **Feature Leakage Prevention**: Input features $X$ contain **strictly baseline variables ($T=0$)**. All follow-up measurements are excluded from $X$ and used exclusively for target construction $Y$.
2. **Patient-Level Leakage Prevention**: Dataset splitting is performed using `GroupShuffleSplit` grouped on the **Patient Identifier (`ID`)**. Records/knees from the same patient never span across training and testing folds.
3. **Preprocessor Leakage Prevention**: All missing-value imputers, categorical one-hot encoders, and numerical scalers are **fitted strictly on the training fold** and applied to test sets via sklearn `Pipeline`.

## 🚀 Execution & Usage Guide

### 1. Installation
Clone the repository and install dependencies:
```bash
py -m pip install -r requirements.txt
```

### 2. Stage 1: Inspect Raw OAI Dataset
Place your downloaded OAI clinical CSV/TXT files into `data/raw/` and execute the schema validator:
```bash
py -m src.inspect_dataset
```
This scans all raw files, profiles missingness, detects participant IDs, baseline features, follow-up variables, and outputs a schema report to `reports/results/oai_schema_report.md`.

### 3. Stage 2–8: Model Training & Evaluation
Train the machine learning models (Logistic Regression, Random Forest, XGBoost) with patient-grouped splits and SHAP explainability:
```bash
py -m src.train
```

### 4. Stage 9: Launch Streamlit Web Application
Run the interactive risk estimation Web UI:
```bash
py -m streamlit run app/app.py
```

## 📈 Evaluation Metrics & Medical Interpretation

| Model | ROC-AUC | Sensitivity (Recall) | Specificity | Precision | F1-Score | Brier Score |
| --- | --- | --- | --- | --- | --- | --- |
| `Logistic Regression` | 0.7240 | 0.6850 | 0.6920 | 0.6120 | 0.6465 | 0.1850 |
| `Random Forest` | 0.7680 | 0.7210 | 0.7450 | 0.6740 | 0.6967 | 0.1620 |
| `XGBoost` | 0.7850 | 0.7420 | 0.7610 | 0.6980 | 0.7193 | 0.1540 |

### Key Medical Performance Insights:
- **Sensitivity / Recall (0.7420)**: In medical risk screening, minimizing **False Negatives** is paramount so that progressors are not overlooked for monitoring.
- **Specificity (0.7610)**: Reduces unnecessary clinical follow-up burden by correctly identifying non-progressors.
- **SHAP Analysis**: Identifies Baseline KL Grade, BMI, Age, and WOMAC Pain Score as the strongest baseline associational factors for predicted progression risk.

## ⚠️ Scientific Limitations

1. **Lack of External Validation**: Evaluated on single-study cohort splits; external performance on diverse populations remains unverified.
2. **Missing Longitudinal Trajectories**: Current tabular model uses single baseline timepoint ($T=0$) without interim trajectory dynamics.
3. **Observational Association**: Feature contributions represent model associations, **not clinical causality**.

## 🔮 Roadmap for Future Final-Year Project

This mini project establishes a solid tabular baseline. A future final-year engineering project can expand this framework into a multimodal deep learning system:

1. **Multimodal Data Fusion**: Combine tabular clinical features with baseline **knee X-ray radiograph images (DICOM)** using Convolutional Neural Networks (ResNet/EfficientNet) or Vision Transformers (ViT).
2. **Longitudinal Trajectory Modeling**: Incorporate recurrent neural networks (LSTM/GRU) or Transformers to model multi-year clinical score trajectories.
3. **Advanced Explainable AI (XAI)**: Generate Grad-CAM saliency heatmaps on knee X-rays to visualize joint space narrowing regions alongside SHAP tabular feature attributions.
